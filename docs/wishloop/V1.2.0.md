# WishLoop 1.2.0（202）

2026-09-07。本版增加首页紧凑模式、Android 桌面小组件、兴趣分类和拖动排序。继续使用 Provider、原有 sqflite 数据库、Material 3、主题、提醒和国际化系统。

## 使用方式

- **首页布局**：点击首页右上角的布局按钮，可切换“紧凑模式”和“兴趣优先”。默认启用紧凑模式；愿望可展开查看，布局选择在重新打开 App 后保留。
- **桌面小组件**：设置 → Android 桌面小组件 → 添加到主屏幕。也可以在 Android 桌面长按空白处，从系统小组件列表选择 WishLoop。点击余额进入账户，点击愿望进入愿望页，点击兴趣打开当天的完成/撤销面板。尺寸较小时自动减少内容，最多显示三个今日兴趣。
- **分类**：兴趣 → 管理分类，支持创建、改名、删除和排序。在兴趣编辑页选择分类；兴趣页可筛选全部、未分类或指定分类。
- **拖动排序**：按住兴趣卡片右侧的排序柄上下拖动。首页和桌面小组件同步使用这个顺序。在某个分类内排序时，其他兴趣的相对位置保持不变。
- **删除分类**：二次确认后，将关联兴趣移到“未分类”，保留兴趣、历史打卡、奖励、扣减和愿望兑换记录。

新增文字提供简体中文、繁体中文和英文，其余语言沿用现有英文回退机制。

## 数据和实现

**数据库版本仍为 10，没有新增表或列，不需要迁移或清空数据。** 分类复用 `mh_groups`；兴趣归属复用 `mh_habits.group_id`；兴趣和分类的顺序复用各自的 `sort_position`。现有完整备份已包含这些字段，本版增加了分类与排序的备份恢复测试。

账户仍以 `hw_transactions` 的整数分账本求和为准。新增界面、小组件和排序不会修改完成/撤销/兑换的账本规则。

桌面小组件使用 Android `AppWidgetProvider`、`RemoteViews` 和 Flutter `MethodChannel`，没有引入新的 Flutter 插件或后台服务。它只保存一份私有的展示缓存；完成和撤销仍由 App 中原有 Controller/Repository 的 SQLite 事务执行。小组件导航使用独立的显式 Intent，避免与 Flutter 默认 URI 导航重复处理。

每次编辑、打卡、撤销、兑换或导入后，重建当天数据和后续六天日程缓存。缓存始终以真实今天为基准，用户在 App 中查看历史日期不会改变桌面“今天”的含义。多次刷新会串行合并，最终发布最新快照。未来日程复用原有频率、星期和完成配额规则。

原生组件根据横竖屏尺寸选择布局，并跟随 App 的主题选择。系统定期更新间隔设置为 30 分钟；App 内操作后主动刷新。平台依据：[Android widget updates](https://developer.android.com/develop/ui/views/appwidgets/advanced)、[AppWidgetManager](https://developer.android.com/reference/android/appwidget/AppWidgetManager)。

## 当前限制

- 小组件点击兴趣后进入 App 操作；桌面缓存不是独立账本。
- 七天都没有打开 App 时，小组件会提示打开以更新今天的兴趣；系统更新时机也受 Android 和桌面启动器控制，不承诺零点即时刷新。
- 已验证 API 36 模拟器的系统桌面，尚未连接实体手机验证各厂商桌面。部分桌面不支持从 App 直接添加时，会给出手动添加方法。
- 本地布局偏好保留在本机，完整数据备份包含分类及排序；桌面摆放和组件尺寸由 Android 桌面管理。
- Gradle/AGP 的未来兼容性提示仍存在，不影响本版构建；本机 Maven 镜像设置见 [BUILD.md](BUILD.md)。

下一步优先收集实体手机上的桌面兼容性、紧凑布局和拖动手感反馈，再决定是否增加更多小组件内容。
